高音補正は、元の音に無い高域を足す処理です(復元ではなく「もっともらしい音」の生成)。既定ではMP3などの非可逆音源だけに掛けます。「CD・ハイレゾにも掛ける」を選ぶと全ての音源に掛かります。AI版(open-audio-sr)は出力が48kHzなので、48kHz以下の音源(CD等)だけに使い、それより高いレートの音源はレートを下げないようリアルタイムEQにします。 / Treble restoration adds high frequencies that were not in the source (plausible generation, not recovery). By default it applies only to lossy sources such as MP3; the "also CD & hi-res" option applies it to every source. The AI version (open-audio-sr) outputs 48 kHz, so it is used only for sources at 48 kHz or below; higher-rate sources get the real-time EQ so their rate is never reduced.

32bitは、排他モードでDACへ渡す形式です。32bitを受け付けない機器は自動で24bitに落とします。内部処理は32bit浮動小数点(有効な仮数は24bit)のため、32bitにしても実際の分解能が24bitを超えるわけではなく、多くのDACも24bitまでです(変換回数を減らし余裕を持たせる効果)。 / 32-bit is the format sent to the DAC in exclusive mode; devices that reject it fall back to 24-bit. Internal processing is 32-bit float (24-bit mantissa), so real resolution does not exceed 24-bit and most DACs stop at 24-bit; the benefit is headroom and one fewer conversion stage.

元の映像が目標より低いときだけ、高品質のlanczos補間で引き上げます(高い映像は縮めません)。補間であり、失われた細部を復元するAI超解像ではありません(AI超解像は「4.3」の変換機能で行えます)。音声は映像と別に取り出し、open-barエンジンでアップサンプリングしながら再生します。4Kは変換に時間がかかります。 / Only video below the target is enlarged, with a high-quality lanczos filter (larger video is never shrunk). This is interpolation, not AI super-resolution that restores detail (use section 4.3 for that). Audio is extracted separately and played through the open-bar engine with upsampling. 4K takes longer to convert.

        3. 音声フォーマットへ変換(複数選択可)

        ハードウェア(DAC)が対応していれば、DSD音源はそのまま再生されます。対応していない場合は、(DSD対応の再生ソフトなら)自動的にPCM音源に変換されて再生されます。そのため、通常はPCM版を別に作る必要はありません。ただし、DSFに対応していない再生ソフト(標準のWindowsプレーヤーなど)では再生できません。 / If your hardware (DAC) supports DSD, the DSD audio is played as is. If it does not, a DSD-capable player automatically converts it to PCM for playback, so you normally do not need a separate PCM version. Players without DSF support (such as the standard Windows player) cannot play it at all.

        DSDを作成するときは、PCM(WAV/FLAC/高解像度PCM)は同時に作りません(選択していても自動で除外します)。 / When creating DSD, PCM (WAV/FLAC/high-res PCM) is not created alongside it (automatically skipped even if checked).

        DoP対応DAC+ビットパーフェクト再生専用(音量調整・SRCを通るとノイズ)。PCMレートはDSDレート/16(DSD64=176.4k、DSD128=352.8k、DSD256=705.6k、DSD512=1411.2kHz。384kHzは48kHz系DSDの入れ物で本ツールのDSDとは一致しません)。 / For DoP-capable DACs with bit-perfect playback only (volume control or resampling turns it into noise). PCM rate = DSD rate / 16 (DSD64 = 176.4k, DSD128 = 352.8k, DSD256 = 705.6k, DSD512 = 1411.2 kHz; 384 kHz belongs to 48 kHz-family DSD, which this tool does not produce).

        ※DSDを作成するときはPCM版を同時に作りません。DSD非対応のハードウェアでは再生側が自動でPCMへ変換するため、PCM版は容量の無駄になります。
        When creating DSD, no PCM version is written alongside: on hardware without DSD support the player converts to PCM automatically, so a PCM copy only wastes space.
        ※DSDはPCM→1bitのΔΣ変調で自前変換しDSFファイルとして保存します(ffmpegはDSDを書き出せないため)。ファイルが非常に大きく(ステレオ1分あたり DSD64≈42MB、DSD128≈85MB、DSD256≈170MB、DSD512≈339MB、DSD1024≈678MB)、高レートほど変換に時間がかかります。音量は安定性のため-6dBに抑えます。Super Audio CDの規格ディスクではなくDSFファイルです。DSD非対応の機器・アプリでは再生できないか、再生ソフト側でPCMへ変換されます(ファイル自体には自動変換の仕組みはありません)。
        DSD is produced by our own PCM-to-1-bit delta-sigma converter and saved as DSF (ffmpeg cannot write DSD). Files are very large (per stereo minute: DSD64 ~42 MB, DSD128 ~85 MB, DSD256 ~170 MB, DSD512 ~339 MB, DSD1024 ~678 MB) and higher rates convert slowly. Level is reduced by 6 dB for stability. This is a DSF file, not a Super Audio CD disc. Devices/apps without DSD support may not play it, or the player software converts it to PCM — the file itself has no automatic fallback.

        3.5. AIノイズ除去(音声) / AI noise reduction (audio)


        ※これは実際の学習済みAIモデル(RNNoise、リカレントニューラルネットワーク、CPUで動作)による処理で、これまでの「AI最適化」のような簡易ヒューリスティックではありません。ただしRNNoiseは主に人の声で学習されたモデルのため、音楽では効果が控えめで高域がやや鈍る場合があります。強さを下げると原音に近くなります。音声の超解像(高音質化)モデルは未実装です。
        This uses a real trained neural network (RNNoise, a recurrent network, runs on the CPU) — not a heuristic like the earlier "AI-optimized" options. It is trained mainly on speech, so on music the effect is modest and highs may dull slightly; lower the strength to stay closer to the original. Audio super-resolution is not implemented yet.

        3.6. AI高域生成(帯域拡張、実験的) / AI bandwidth extension (experimental)



        ※学習済みモデル(LavaSR、Apache-2.0、初回のみ約56MBを自動ダウンロード)で欠けた高域を生成して足します。入力の帯域は一切変更せず、生成した高域は入力の包絡を外挿した値を上限に頭打ちにします(生のモデル出力は音楽で元信号から離れて悪化したため、この設計にしています)。 実測: 音楽素材を8kHz/12kHzで帯域制限して試すと、正解の存在する帯域のスペクトル距離(LSD)が無処理より改善(3.4→1.5、2.7→1.6)し、低域は完全に保たれました。
        ※これは「復元」ではなく合成で、LSDは聴感品質そのものではありません。帯域が欠けていない音源(約20kHzまである)には何もしません。ロッシー音源で元から捨てられた高域を「本物の音」として取り戻せるわけではありません。音声専用出力とDSD向けで、AIノイズ除去(3.5)と併用するとノイズ除去が先に行われます。
        Generates the missing highs with a trained model (LavaSR, Apache-2.0; ~56 MB is downloaded on first use). The existing band is never modified, and the generated highs are capped by an extrapolation of the input's spectral envelope (the raw model output moved music away from the original, hence this design). Measured on music band-limited at 8/12 kHz, the log-spectral distance in the band where ground truth exists improved over no processing (3.4→1.5, 2.7→1.6) while the low band stayed identical. This is synthesis, not restoration, and LSD is not perceptual quality. Sources that are not band-limited (content up to ~20 kHz) are left alone. It cannot bring back highs that a lossy encoder discarded. Audio-only/DSD outputs; with AI noise reduction (3.5) the denoise runs first.

        3.7. チャンネル構成(モノ/ステレオ⇔サラウンド変換) / Channel layout (mono/stereo ⇔ surround)

        全ての音声出力形式(3.)に適用されます。
        モノラル/ステレオ → 5.1ch・7.1ch: 元に無い音を新たに生成するわけではない、単純な複製・按分による 疑似(バーチャル)サラウンドです(実際のディスクリート5.1ch/7.1ch音源が持つ情報量には及びません)。 センターは左右の単純ミックス、リア/サイドは前方の減衰コピー、LFE(低音効果音)は常に無音にします。 元から3ch以上ある音源には適用しません(想定外のチャンネル対応付けを避けるため)。
        サラウンド → ステレオ/モノラル: ffmpeg標準の降ミックス(疑似ではありません)。

        Applies to every audio output format (3.). Mono/stereo → 5.1ch/7.1ch is a simple duplication/mix-based pseudo (virtual) surround — it does not generate sound that wasn't in the source, and falls short of a true discrete 5.1/7.1 source. Center is a plain mix of left+right, rear/side channels are attenuated copies of the front, and LFE is always silent. Sources that already have 3+ channels are left untouched (to avoid an unintended channel mapping). Surround → stereo/mono uses ffmpeg's standard downmix (not pseudo).

          4.1. Dolby/サラウンド対応の範囲 / Dolby & surround support

          Dolby Vision / Dolby Atmos / Dolby Cinema / IMAX Enhanced / 4DX は各社のライセンス制フォーマットで、make-diskがこれらを新規に生成(エンコード)することはできません。代わりに、(1)元素材に含まれるDolby Vision・Atmos・5.1/7.1サラウンドを壊さない「無変換コピー」、(2)互換性のある下位形式(HDR10、Dolby Digital / Digital Plus、AAC/Opusのサラウンド)への変換、(3)元素材の検出結果のログ表示、に対応します。
          These are licensed formats; make-disk cannot newly encode Dolby Vision / Atmos / IMAX / 4DX. It can (1) losslessly copy existing Dolby Vision / Atmos / surround tracks, (2) convert to compatible lower formats (HDR10, Dolby Digital / Plus, surround AAC/Opus), and (3) report what it detects in the source. HDR10 conversion keeps the base layer; Dolby Vision dynamic metadata is dropped.

          4.3. AI超解像とフレーム補間 / AI super-resolution and frame interpolation

          
        
          
          ※実行方式は自動で選びます: 初回にこのPCのCPUとGPUを実測し、CPUのみ/GPUのみ/併用のうち最も速い方式を使います(結果は保存され、CPUの構成が変わると再測定)。open-cudaにはGPUの畳み込み演算が無く、AI計算そのものはCPU(自前のAVX2+FMA)とVulkan(NCNN)で行っています。
          
          ※非常に時間がかかります。「下調べ」で見積もりを確認してください(720×480の1コマ: CPU(32スレッド)約1.3秒、GT 730 GPU約2.8秒、併用で約1.3倍)。映画1本は数日規模になり得ます。途中で中止しても、同じ設定でもう一度実行すれば続きから再開します。
          
          ※真っ黒・単色・ほぼ静止のコマはAIを通さず再利用します。これが減らすのは主に計算時間で、ディスク容量への効果は小さいです(エンコーダは静止画面にほとんどビットを使わないため)。
          
          ※フレーム補間(RIFE)は近似です。動きの大きい場面・場面転換でゴーストやゆがみが出ることがあり、本当に120fpsで撮影した映像と同じにはなりません。4Kでは非常に遅く、一時的に数GBのディスクを使います。初回のみプラグイン(約12MB)を取得します。
          
          ※初回のみAIのプラグイン(約45MB、MIT)を自動ダウンロードします。解像度の指定(4.2)や6.のアップコンバートと併用すると、AI拡大後に指定の解像度へリサイズします(例: DVD→4K)。
          
          Device choice is automatic: the first run measures this PC's CPU and GPU and uses the fastest of CPU-only / GPU-only / both (cached; re-measured if the CPU changes). open-cuda has no GPU convolution, so the AI math itself runs on our own AVX2+FMA CPU kernel and Vulkan (NCNN).
          
          Very slow — check "Estimate" first (per 720x480 frame: CPU 32 threads ~1.3 s, GT 730 GPU ~2.8 s, both ~1.3x faster). A feature film can take days. If you cancel, running again with the same settings resumes.
          
          Black / flat / near-static frames skip the AI; that mainly saves compute time and has little effect on disc capacity (encoders spend almost no bits on still images).
          
          Frame interpolation (RIFE) is an approximation: fast motion and scene cuts can show ghosting or warping, and the result is not the same as real 120 fps footage. It is very slow at 4K and temporarily uses several GB of disk. The plugin (~12 MB) is fetched on first use. The AI plugin (~45 MB, MIT) is downloaded on first use; combined with a resolution preset (4.2) or the section 6 upconvert, the result is resized to it (e.g. DVD→4K).

          7.5. 再生規格の上限(kHz・ビットレート)に収める / Fit within a playback standard's maximum (kHz & bitrate)
          
        
        
          
        
          選んだ規格の最大サンプリング周波数・ビット深度・ビットレートを超えないように変換します(元がそれ以下ならそのまま。アップサンプリングはしません)。上限を超える高解像度PCM/DSDの形式は、家庭用プレーヤーの規格外である旨を表示します。 / Converts so the chosen standard's maximum sample rate, bit depth and bitrate are not exceeded (sources already below are left as is; no upsampling). High-res PCM/DSD formats above the limit are reported as outside the player standard.
          
      
          

      
          
        
          8. 時間指定・トリミング(区間カット)
          
        
          
          時間・区間の指定は、この8.にまとめてあります(以前は7.5と8.に分かれていて分かりにくかったため、
          2026-09-28にここへ統合しました)。全ファイルまとめて先頭から機械的に切るだけでよいなら
          8.1、動画/音声を見ながら・聞きながら、途中の不要な部分だけをマウスや時:分:秒で
          精密に指定したいなら8.2を使ってください(両方を同じファイルに使うと8.2が優先されます)。
          
          Every time/range input now lives here in section 8 (previously split across 7.5 and 8, which
          was confusing — consolidated 2026-09-28). Use 8.1 to mechanically keep just the start of
          every file; use 8.2 to precisely mark unwanted parts anywhere in a file while watching/
          listening, or by typing h:m:s (8.2 takes priority if both are set for the same file).
        
          

        
          8.1. 全ファイル一括: 先頭から◯◯だけ残す / All files at once: keep only the first ◯◯
          
        
          
          元データをサイズでカットするか、時間でカットするかを、それぞれYES/NOで選びます。
          
          Answer YES/NO for cutting the source by size and by time.
        
          
        
          元データをサイズでカットする？ / Cut the source by size?
          
          
          — 1ファイルあたり / per file:  MB(先頭から / from the start)
        
          
        
          元データを時間でカットする？ / Cut the source by time?
          
          
          — 時
          分
          秒(先頭から / from the start)
        
          
        
          サイズと時間は必ずどちらか一方だけがYESです(片方をYESにするともう片方はNO、NOにするともう片方がYESになります。既定はサイズ)。数値が空欄なら、そのファイルはカットしません。 / Exactly one of size/time is YES (switching one flips the other; size is the default). If the value is left blank, nothing is cut.
          
        
          サイズでカットする場合は、元データのサイズを基準に、指定サイズに収まる長さだけを先頭から残します。8.2で手動のカット区間を指定したファイルは変更しません。 / Cutting by size keeps only as much from the start as fits the given size of the source data. Files with manual cut ranges (8.2) are left untouched.
          

        
          後処理 / Post-processing
          
        
        
          
        
        
          
          ※「AI判断」はffmpegの無音検出(音量ベース)による近似です。実際の意味的なシーン解析は行いません。
          
          Note: "AI-judged" is an approximation using ffmpeg's volume-based silence detection — it does not perform true semantic scene analysis.
        
          

        
          8.2. ファイルごとの精密カット(個別編集) / Per-file precise cutting (individual edit)
          
        
          
          各ファイルの「編集...」から、カットしたい区間(最初・途中・最後、いくつでも)を
          動画を再生して見ながらマウスで、または時:分:秒を直接数字で入力して指定できます。
          動画は再生し続ける必要はなく、シーク(早送り位置指定)だけで確認できます。
        
          
        
        
          先に「1.」でファイルを追加してください。 / Add files in section 1 first.
          
        
          
      
          

      
          
        
          8.5. 複数ファイルの合成・分割編集 / Composite & split editing across multiple files
          
        
          
          ソースの音声/動画ファイルを選択した順に結合(合成)したり、1本の長い動画/音声を
          等間隔またはサイズ指定で複数ファイルに分割したりできます(静止画・PDFの合成は
          「4.5」のPDF見開き変換を参照)。
          
          Concatenate the source audio/video files (in list order) into one, or split one long
          file into multiple parts at equal intervals or by target size (image/PDF compositing
          is handled separately in section 4.5).
        
          
        

        
          分割(1つのファイルを、複数のファイルに分ける) / Split (cut one file into several files)
          
        
        
          
        
        
          
        
        
          
        
        
          分割されるのは、ソース一覧の先頭にある音声・動画ファイル1本だけです。個数は0(分割しない)または2以上です。1は「分けない」と同じなので飛ばし、▲▼で0と2の間を移動します。「大きさで分ける」で、ファイル全体が指定サイズ以下のときも分割されません。 / Only the first audio/video file in the source list is split. The count is 0 (no split) or 2 and up; 1 would mean the same as not splitting, so the arrows skip it (0 ↔ 2). With "by size", a file already at or below the size is not split either.
